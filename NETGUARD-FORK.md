# NetGuard Download Manager: fork notes

NetGuard Download Manager is a fork of **Mister Download Manager 0.5.2**
(<https://github.com/anefzaoui/misterdownloadmanager>), Copyright (C) Ahmed Nefzaoui and
contributors, under the GNU General Public License v3.0 or later. `LICENSE` and all original
copyright notices are unchanged. The fork changes the product name, the logo and icons, and the
colour theme. It does not change the download engine, features, layout, database or settings
formats, dependencies, framework versions or the structure of the GitHub Actions workflow.

## Status of verification (read this first)

The changes were made in an environment with **no Rust toolchain and no network access**.
Therefore:

- **Not verified:** `cargo build`, `cargo test --workspace`, `cargo fmt`, `cargo clippy`, the
  Inno Setup installer build, and the GitHub Actions run. Nothing here claims they succeed.
- **Verified:** the browser-extension test suite (`node tools/extension/test.mjs`, 69 checks
  passed), all JSON files parse, the JS files pass `node --check`, the icon scripts run, the
  English catalog was regenerated with `tools/i18n/extract.py`, and the colour pairs that the
  palette's contrast tests check were computed by hand with the same WCAG formula (all pass).
- The first real compile and test run will be your first GitHub Actions run. If it fails,
  the likeliest causes are in section "Known risks" below.

## What changed

### 1. Branding
- "Mister Download Manager" became "NetGuard Download Manager" in UI strings (`crates/*/src`),
  the window title (`MAIN_TITLE` in `crates/app/src/main.rs`; the two integration tests that look
  the window up by title use the same text), tray/desktop entries, the exe version info
  (`crates/app/build.rs`), the installer (`tools/installer/mdm.iss`, `build.ps1`, the 86
  installer language files), the browser extension (name, locales, popup, comments), the phone
  remote page, Dockerfile/compose files, issue template, README and user docs in `docs/`.
- The short name "MDM" became "NetGuard" wherever it is user-visible.
- All 86 `i18n/*.tsv` catalogs got the same replacement in both the source and translated
  columns, and `i18n/en.tsv` was regenerated by `tools/i18n/extract.py`, so source strings and
  catalogs stay in step.
- `crates/crash/tests/e2e.rs` expects "Description: NetGuard crashed" to match the crash report text.

### 2. Logo and icons
- New logo: a shield with a download arrow, emerald (#10B981/#059669) on navy (#0B1220/#17243A).
- Master art: `art/NetGuard Download Manager.png` (2048 px), drawn by
  `tools/icon/make_netguard_logo.py`. `tools/icon/build_icon.py` builds from it:
  `crates/app/assets/icons/app/mdm-{16,20,24,32,48,64,128,256}.png`, `mdm.ico`,
  `extension/icons/icon-{16,32,48,128}.png`. 16-32 px use a simplified drawing.
- `extension/video.js` embeds `icon-48.png` as a data URI; it was refreshed (a test checks it).
- `docs/images/logo.png` was replaced. The old `art/Mister Download Manager.png` was removed.
- Every place the app and build read an icon uses the new files under the original names:
  `crates/app/assets/icons/app/mdm-*.png` (window, tray, About, help, Remote page),
  `mdm.ico` (the exe's icon via `crates/app/build.rs`, and the installer's `SetupIconFile`),
  `extension/icons/icon-*.png` (all three manifests). No other file in the project holds the old logo
  except the screenshots listed under "Known risks".
- Also replaced with NetGuard artwork, under their original names: `docs/images/social-preview.png`
  (new picture; it no longer shows the old app window) and the website's `favicon.ico`,
  `assets/logo-64.png`, `logo-256.webp`, `logo-640.png`, `apple-touch-icon.png`, `favicon-32.png`.
- Icon file names (`mdm-*.png`, `mdm.ico`) were kept because the build refers to them.

### 3. Colour theme
Only values in the `palette!` table of `crates/app/src/palette.rs` changed, in the **classic
look's dark variant**, using constants `NG_*`:

| Role | Colour |
|---|---|
| Main background (window, download list) | #0B1220 |
| Secondary background (sidebar, menu bar, title bars, inputs) | #111C2E |
| Surface (tab pages, menus, buttons, dialogs' panels) | #17243A |
| Primary accent (selection, progress, default button, checks, links) | #10B981 |
| Hover accent | #059669 |
| Primary text | #F8FAFC |
| Secondary text | #94A3B8 |
| Borders, dividers, neutral hover fills | #26354B |

Two derived tones, because the palette has no colour for those states: `#64748B` (disabled
text/icons, scroll thumbs) and `#047857` (pressed accent button). Text on accent fills is the
main background colour (#0B1220) so it passes the 4.5:1 contrast the tests require.

Also: the segmented progress bar uses an emerald gradient and navy "missing" rows in dark;
the phone remote page's CSS variables use the palette (`crates/remote/web/app.css`); the unit
test that pins the classic dark anchor values in `palette.rs` was updated.

`Settings::default().always_dark` is now `true` (`crates/app/src/settings.rs`), so a fresh
install shows the navy/emerald look even when Windows is in light mode. Saved settings win, and
View → Always dark still turns it off.

### 4. Deliberately unchanged
- Download engine, protocol code, database/settings formats, config keys, crate and module names.
- `LICENSE`, `CHANGELOG.md`, `ROADMAP.md`, the licence headers and the original author's credits.
- Compatibility identifiers: the credential-store service name (`SERVICE` in
  `crates/app/src/secrets.rs`) and the drop-target window id, so saved sign-ins keep working;
  the data folder, registry keys, running-mutex name, installer `AppId`, native-messaging host
  name, exe and installer file names (`MisterDownloadManager-<version>-setup.exe`).
- `.github/workflows/*`, except one line: the GitHub Release title in `release.yml` now reads
  "NetGuard Download Manager vX.Y.Z" (it was hard-coded). The light variant of the classic look and the other
  built-in themes (Luna, Aero, Metro, ...), the marketing `website/` folder, `i18n/site` and `i18n/style`.

## Known risks and limits

0. **Old screenshots and website text.** The screenshots in `docs/images/*.webp` (and the README
   and `website/` pages that show them) were taken of the original app, so they still show its old
   window title and logo. They can only be replaced by running the app and retaking them
   (`tools/shots`). The website's wording (`website/*.html`, `i18n/site`) was not rewritten, and
   `pages.yml` would publish it if you enable GitHub Pages: leave Pages off or edit it first.

1. **Updater points to upstream.** Help → Check for updates reads the original project's
   GitHub releases and verifies them with the original author's signing key
   (`crates/app/src/help.rs`, `crates/tools/src/lib.rs`). The fork cannot sign with that key, and
   an update from upstream would install the original Mister Download Manager over NetGuard.
   Change the repository and key, or avoid using the updater, before distributing builds.
2. **Formatting.** The new name is two characters longer, so a few lines may no longer match
   `rustfmt`. Run `cargo fmt --all` and commit. The Release workflow does not check formatting;
   the CI workflow does.
3. **Light mode** still has the original blue accents (the tests pin those values).
4. **Links in README/docs** (download badges, store links, star count) are upstream's.
5. **Installer file name** keeps the original (see above); the installer's displayed name,
   Start menu entries and wizard text say NetGuard. Rename the file after downloading if you like.
6. **Unsigned installer.** Without a code-signing certificate, Windows SmartScreen will warn.

## Uploading to GitHub

1. Create an empty repository on GitHub (no README, licence or .gitignore), e.g. `netguard`.
   Keep it **public** if you want unlimited free Actions minutes (private repos have a quota,
   and Windows minutes count double).
2. Unzip the archive. The folder `NetGuard-Download-Manager/` is the repository root.
3. In that folder, run:
   ```
   git init -b main
   git add .
   git commit -m "NetGuard Download Manager: branding and theme"
   git remote add origin https://github.com/YOUR-USER/YOUR-REPO.git
   git push -u origin main
   ```
   (`git add .` respects the included `.gitignore`. If Windows warns about line endings, that
   is harmless.) You can instead use GitHub Desktop or "Add file → Upload files", but uploads
   through the web page are limited to 100 files at a time, which this project exceeds, so use git.
4. Before pushing, optionally run `cargo fmt --all` (needs the Rust toolchain from
   `rust-toolchain.toml`).

## Building the Windows installer with GitHub Actions

1. Open your repository on GitHub → **Actions**. If asked, click "I understand my workflows, enable them".
2. In the left list choose **Release** (`.github/workflows/release.yml`).
3. Click **Run workflow**, pick branch `main`, and run it. Running it by hand builds and
   tests everything but does not publish a release (publishing happens when you push a `v*` tag).
4. Wait for the run to finish (the Windows job installs Rust, runs `cargo test --workspace`, builds
   the app and then the installer with Inno Setup). Expect it to take a while.
5. Open the finished run. Under **Artifacts** download the one named **windows**. It is a ZIP
   holding the installer `MisterDownloadManager-<version>-setup.exe` (the file name is the
   original's; the installer's own text says NetGuard Download Manager), plus a portable ZIP and a
   plain ZIP (per `tools/installer/build.ps1`). Unzip it and run the `-setup.exe`.
6. To get a GitHub Release instead: make sure the tag matches the version in `Cargo.toml`
   (`0.5.2`), then `git tag v0.5.2 && git push origin v0.5.2`. The workflow's final job publishes
   the release with the Windows, extension, Linux and macOS builds. The secrets are optional:
   without `MDM_RELEASE_KEY` the release is created unsigned (the log warns that the checksum list
   is unsigned), without a code-signing certificate the installer is unsigned. The extension
   store-upload steps only run when their tokens exist.
7. If the run fails, open the failing step. A failing test or a compile error is the thing to
   fix first; send me the log and I will help.

## Building locally on Windows 10/11 (optional)

1. Install Visual Studio Build Tools (C++ workload), `rustup` (it installs the toolchain pinned by
   `rust-toolchain.toml`), and Inno Setup 6.
2. In the project folder: `cargo build --release --workspace`, then `cargo test --workspace`.
3. Installer: run `tools/installer/build.ps1` as described in its header.
